JDBC client:
===========

Java app <-----------> DB software.

--In Java-DB communication, our Java application will act as a client because Java application needs the services of the DB server. so our Java application will act as a JDBC client.


Responsibilities of the JDBC client:
====================================

1. Requesting the DB connection.

2. Submitting the appropriate SQL statement to the db server in the form of String object.

3. Processing the result given by the DB server.

4. Dealing with exceptions if any.

5. Managing the transactions whenever it is required.

6. Closing the connection once done with the DB operation.



JDBC driver :
===========

--It is a translation software written in Java  according to the JDBC specification.(it comes in the form of a .jar file)


Responsibility of Jdbc driver software:
======================================

1. Establishing the connection. (Connects Java application with the database)

2. Receiving the Jdbc method calls (Java method calls) and translate them into the DB understandable format(sql) and forward them to the DB software.

3. Translating the DB software given result in the Java format (Java objects) and returns that object to the JDBC client.



Steps to connect our Java application with the DB sever (MySQL):
================================================================


1. Download/get the jdbc driver related jar file (mysql-connector.jar) from the internet and set that jar file inside the classpath of our Java application.

2. Load the driver related main class into the memory. (com.mysql.cj.jdbc.Driver)

3. Prepare the connection String(URL).

4. Establish the connection

5. After performing the CRUD(Create record, retrieve, update, delete ) operation close the connection.

Static and Non-static blocks in Java:
=====================================

--In Java, a class can contain:

1. Static blocks (also called static initialization blocks)
2. Non-static blocks (also called instance initialization blocks)
3. Constructors
4. Methods

--These blocks are used to initialize objects and class-level data. and we can write the logics(Executable codes)




1. Static Block
----------------

--A static block is a block of code written using the static keyword.

syntax:

static{
    // code
}



Important Points:

--Static blocks are executed only once.

--They are executed when the class is loaded into memory.

--Static blocks execute before the main() method.

--Mainly used for initializing static data/resources.

--A class can contain multiple static blocks.

--Static blocks execute in the order they are written.




2. Non-Static Block (Instance Initialization Block)
---------------------------------------------------

--A non-static block is a block without the static keyword.

syntax:

{
	//code
}



Important Points:

--Non-static blocks execute whenever an object is created.

--They execute before the constructor.

--They execute every time a new object is created.

--Mainly used for common initialization code.




Example:
--------

A.java:
--------


package com.masai;

public class A {

    // Non-static block
    {
        System.out.println("inside non-static block");
    }

    // Static block
    static{
        System.out.println("inside static block");
    }

    // Constructor
    public A() {
        System.out.println("inside constructor of A");
    }

    // Instance method
    public void funA() {
        System.out.println("inside funA of A");
    }

    public static void main(String[] args) {

        System.out.println("inside main method");

        A a1 = new A();

        a1.funA();
    }
}


Output:
-------

inside static block
inside main method
inside non-static block
inside constructor of A
inside funA of A



Why Use Non-static Blocks?

A/- If multiple constructors contain common code, instead of repeating the same code in every constructor, we can place that common code inside a non-static block.




Note: A static block can contain any valid Java code, including object creation and method calls.


Example:

A.java:
--------

package com.masai;

    static {

        System.out.println("inside static block of A");

        // Creating object inside static block
        A a1 = new A();

        a1.funA();
    }

    public void funA() {
        System.out.println("inside funA of A");
    }
}

--Once we get the Connection object, we can execute SQL statements from our Java application.

--To execute SQL statements, we require an object of the java.sql.Statement interface.

--We get the Statement object by using:

Statement st =  conn.createStatement();

--createStatement() method of Connection object creates and returns a Statement object.

--To execute SQL statements from Java application, Statement interface provides the following methods:

1. public int executeUpdate(String sql) throws SQLException;

--This method is generally used for SQL statements that modify the database data or structure.

DML Statements
   - INSERT
   - UPDATE
   - DELETE

DDL Statements
   - CREATE
   - ALTER
   - DROP
   - TRUNCATE

--This method will return number of row affected due to the supplied SQL statement.

--For DDL statements: generally it returns 0 because no rows are affected directly.


2. public ResultSet executeQuery(String sql) throws SQLException;

--This method is used for SELECT queries.

--It returns a ResultSet object.


3. public boolean execute(String sql) throws SQLException;

--This method can execute any type of SQL statement.

It returns:

true  -> if ResultSet object is returned
false -> otherwise




Note: In realtime mostly we use the executeUpdate() for DML operations and executeQuery() for the DRL operations, because Database administrator will manage the Database table schema, normalizations, and access privileges on the tables.

Limitations of java.sql.Statement Interface:
===========================================


--If we use Statement object to perform database operations, then it has the following limitations:


1. Complexity in Handling Dynamic Queries:

--When we use Statement object, we generally create SQL queries by concatenating Java variables into SQL String.

As the query becomes larger:

--query creation becomes difficult,
--readability decreases,
--chances of mistakes increase.


2. Performance Problem:


--Whenever a query is executed using Statement object, the Database Engine generally performs the following tasks every time:

--Database Internal Processing
--Query Parsing
--Query Compilation
--Query Optimization
--Execution Plan Generation



Example Query:

select * from student where roll = 10

Again:

select * from student where roll = 20

Again:

select * from student where roll = 30


--Even though only the value changes, the database may repeat:

parsing,
compilation,
optimization,
execution plan generation.

--This repeated processing can reduce performance.



3. SQL Injection Problem:

--Using Statement object with dynamic query concatenation can lead to SQL Injection attacks.


What is SQL Injection?

--SQL Injection is a security vulnerability in which malicious SQL code is inserted into user input.

Because of this:

--unauthorized data access may happen,
--data may be modified,
--data may be deleted.



Example of SQL Injection
------------------------

Suppose we have login code like this:


String sql = "select * from users where username='"+ username+ "' and password='" + password + "'";


Suppose user enters:

username: admin

password: ' OR 1=1 #



Generated SQL becomes:

select * from users where username='admin' and password='' OR 1=1

Condition:

1=1

is always true.

As a result:

authentication may bypass,
unauthorized login may happen.

This is called SQL Injection.

To Overcome These Problems:
---------------------------


Instead of using Statement, we use: java.sql.PreparedStatement interface.


Statement
    |
PreparedStatement


--PreparedStatement is a child interface of Statement.


Advantages of PreparedStatement:
--------------------------------


--PreparedStatement is one of the most commonly used interfaces in JDBC for executing SQL queries.

It provides several advantages over Statement object.

1. Better Performance for Repeated Query Execution:


--When we use Statement object, database engine may perform the following tasks every time a query is executed:

-Query Parsing
-Query Compilation
-Query Optimization
-Execution Plan Generation


Example using Statement:

select * from student where roll = 10

--Even though only values are changing, database may repeatedly process the query.

--This repeated processing can reduce performance.


In PreparedStatement, query structure remains fixed and only values change.

Example:

select * from student where roll = ?

Now:

--query is prepared only once,
--database may compile and optimize the query only at the first execution,
--execution plan may be stored inside database cache,
--next time database can reuse the cached query plan.

--Only parameter values are changed.


2. Helps Prevent SQL Injection Attacks:


--PreparedStatement helps prevent SQL Injection attacks because:

-SQL query structure is fixed,
-user input is treated only as data,
-user input cannot modify SQL query logic.

Later, even if malicious input is provided:

admin' OR 1=1 #

--it is treated as normal String data,
--not executable SQL code.

Therefore:

--unauthorized query manipulation is prevented,
--application security improves.


3. Easier Handling of Dynamic Queries:

--Using Statement object, dynamic queries are created using String concatenation.

--But using the PreparedStatement, placeholders (?) simplify query handling.



4. Better Readability and Maintainability: 

PreparedStatement makes JDBC code:

cleaner,
more organized,
easier to understand,
easier to maintain.

Because:

SQL query and data values are separated,
query structure remains fixed,
code becomes more professional and readable.







Creating PreparedStatement Object:
---------------------------------


--To create a PreparedStatement object, we call:

prepareStatement(String sql) method on the Connection object.



Syntax:

1. Query with Fixed Values:

PreparedStatement ps = conn.prepareStatement("insert into student values(30,'arun','pune',600)");


2. Query with Placeholders:

PreparedStatement ps = conn.prepareStatement("insert into student values(?,?,?,?)");


Here:

? symbols are called placeholders (parameters).
Actual values are supplied later.


Binding Values to Placeholders:


--Before executing the query, we must bind values to placeholders using setXXX() methods.

Example:

ps.setInt(1, 40);

ps.setString(2, "Sunil");

ps.setString(3, "Chennai");

ps.setInt(4, 700);



Note: Placeholder indexing starts from 1, not from 0.



Executing PreparedStatement:
----------------------------

--After binding values, we can execute the query using the following methods:


1. public int executeUpdate() throws SQLException;


2. public ResultSet executeQuery() throws SQLException;


3. public boolean execute() throws SQLException;




Important point:
----------------

In PreparedStatement, SQL query is supplied only once during object creation.

Therefore:
executeUpdate(),
executeQuery(),
and execute() methods do not require SQL String again.

package com.chitkara;

import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.PreparedStatement;

		String password = "root";

		try {
			Class.forName(driverName);
		} catch (ClassNotFoundException e) {
			e.printStackTrace();
		}

		try (

				Scanner sc = new Scanner(System.in);

				Connection conn = DriverManager.getConnection(url, username, password);

				PreparedStatement ps = conn.prepareStatement("insert into student values(?,?,?,?)");

		) {

			int count = 1;

			while (true) {

				System.out.println("Enter Details of Student " + (count++));

				System.out.println("Enter ROll:");
				int roll = sc.nextInt();

				System.out.println("Enter Name:");
				String name = sc.next();

				System.out.println("Enter Address:");

				System.out.println("Enter Marks:");
				int marks = sc.nextInt();

				ps.setInt(1, roll);
				ps.setString(2, name);
				ps.setString(3, address);
				ps.setInt(4, marks);

				int rowsAffected = ps.executeUpdate();

				if (rowsAffected > 0) {
					System.out.println("Record inserted successfully.");
				} else {
					System.out.println("Record not inserted.");
				}

Performing DRL operation (Select operation):
============================================




PreparedStatement ps= conn.prepareStatement("select * from student");
		
ResultSet rs= ps.executeQuery();


--When a SELECT query is executed, database records are returned in the form of a java.sql.ResultSet object.

--ResultSet object stores the records returned by the database query.

The structure of ResultSet object depends upon:


--In order to get the details from the ResultSet object, we should know the structure of the ResultSet object.



Note: ResultSet object structure will depends upon the query what we have executed, it does not depends upon the table structure.




Example1: 

select * from student

ResultSet structure contains:

roll name address marks

--because all columns are selected.

Example2:

select roll,name from student

Now ResultSet contains only:

roll name

--because query selected only these columns.


Example3:

select count(*) from student

Now ResultSet contains only one column:

count(*)

Therefore:

--ResultSet structure depends upon query result,
--not necessarily on full table structure.



--Inside the ResultSet object, records are maintained in a tabular form.

--A special pointer called Cursor is used to point to records.

Initially:

--cursor points before the first record. 

This position is called: BFR (Before First Record)

BFR 
Record1
Record2
Record3
ALR

Where:

BFR:  Before First Record
ALR:  After Last Record

--Initially cursor is always at BFR.

Accessing Data from ResultSet:
-----------------------------

--To access data from ResultSet, we need to perform two tasks:

1. Move Cursor to Record Area

We must move cursor from:

--BFR to actual record area.

For this purpose, ResultSet provides following method:

public boolean next() throws SQLException;


next() method:

--moves cursor to next record,
--returns true if record exists,
--returns false if cursor reaches ALR.




2. Fetching Column Values:

--After moving cursor to a valid record,

--we can fetch column values using following method:

public XXX getXXX(String columnName) throws SQLException;

or 

public XXX getXXX(int columnIndex) throws SQLException;


Here:

--XXX represents appropriate data type method.

Example:


int getInt()

String getString()

double getDouble()

float getFloat()

boolean getBoolean()



Strategy for Processing ResultSet:
-----------------------------------

--The way we process ResultSet
--depends upon expected number of records.


Case 1: At Most One Record Expected

If we are sure that:

query returns either: 0 record or 1 record

then we should use: if-else

Example:

select * from student where roll = 10;

Because: roll is primary key, at most one record can exist.


Example:

if (rs.next()) {

	System.out.println(rs.getInt("roll"));

	System.out.println(rs.getString("name"));

} else {

	System.out.println("Record not found.");
}



Case 2: Multiple Records Possible:

--If query may return multiple records,

--then we should use: while loop


Example:

select * from student where name='Ramesh';

--Because: multiple students may have same name (Non- primary key).


Example:

while (rs.next()) {

	int r = rs.getInt("roll");

	String n = rs.getString("name");

	String a = rs.getString("address");

	int m = rs.getInt("marks");

	System.out.println(r + " " + n + " " + a + " " + m);
}

ResultSetMetaData in JDBC:
=========================

--When we execute a SELECT query in JDBC, the database returns the result in the form of a ResultSet object.

But sometimes, we may not know:

--how many columns are present,
--column names,
--column data types,
--table names,
--column sizes,
--whether column is nullable or not.

To get this structural information about the ResultSet object, JDBC provides:


java.sql.ResultSetMetaData interface.


--ResultSetMetaData is an interface in JDBC that provides information about the structure of the ResultSet object.

It is mainly used to get:

--Number of columns
--Column names
--Column data types
--Column sizes
--Table names
--Nullable information
--Auto increment information


Important Point:

--ResultSetMetaData does NOT contain actual data records.

--It contains only information about: Structure of ResultSet


Suppose:

ResultSet = Student Report Card Data
ResultSetMetaData = Format/Structure of Report Card

Example:

Roll	Name	Marks
101	Ram	500

Here:

Actual records: ResultSet

Whereas ResultSetMetaData is: Column details like:

Roll is INTEGER
Name is VARCHAR
Marks is INTEGER


We can get the ResultSetMetaData object using: 

ResultSetMetaData rsmd = rs.getMetaData();


Here:

rs = ResultSet object
rsmd = ResultSetMetaData object


Important Methods of ResultSetMetaData:
---------------------------------------

1. int getColumnCount(): Returns number of columns.

2. String getColumnName(int index): Returns column name

3. String getColumnTypeName(int index): Returns datatype name

4. String getTableName(int index): Returns table name

5. int getColumnDisplaySize(int index): Returns column display size

6. int isNullable(int index): Checks nullable column// It returns an integer constant.ResultSetMetaData.columnNoNulls, ResultSetMetaData.columnNullable

7. boolean isAutoIncrement(int index): Checks auto increment



Note: Column index starts from 1 not from 0.

Avoiding Hardcode Database Details Inside JDBC Application
===========================================================

--In many beginner JDBC programs, we usually write database details directly inside the Java program.

Example:

String driverClass = "com.mysql.cj.jdbc.Driver";
String url = "jdbc:mysql://localhost:3306/chitkaradb";
String username = "root";
String password = "root";

This is called: Hardcoding

--because values are fixed inside source code.

--Hardcoding database details creates several problems in real-world applications.


1. Security Problem:

--Suppose source code is shared publicly on:

GitHub
Company repository
Backup systems

--Then database credentials become exposed.

Example:

String password = "root";

--Anyone can see the password. This is a major security risk.


2. Difficult Maintenance:

--Suppose database password changes:

From: "root" to "admin123"

Then we must:

--modify source code,
--recompile application,
--redeploy application.

This is inefficient.



3. Different Environments Problem:

--Real-world applications usually have multiple environments:

| Environment | Purpose           |
| ----------- | ----------------- |
| Development | Developer testing |
| Testing     | QA testing        |
| Production  | Live application  |



--Each environment may have different:

database URL,
username,
password,
port number.

--Hardcoding makes environment switching difficult.




Better Approach:
----------------

--Instead of hardcoding values inside Java source code:

--Store configuration outside the application

Examples:

-properties file
-XML file
-YAML file
-environment variables

Most commonly used: .properties file




Using Properties File:
-----------------------

--A properties file stores key-value pairs.

Example:

db.properties:
-------------

driverClass=com.mysql.cj.jdbc.Driver
url=jdbc:mysql://localhost:3306/chitkaradb
username=root
password=root
